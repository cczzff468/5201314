# 一、统一注册表 QQ 条目（src/lib/prompt-entries.ts）

注册表把系统内所有发给大模型的提示词做成可开关/可编辑的「条目」。QQ 相关条目如下（`chatRuleEntries('qq', 'QQ')`，源码 563-672 行 + 合并组 1729-1738 行）。

## 1. qq-rules —— QQ 沉浸规则合并组（v65）
- **文件+行号**：`src/lib/prompt-entries.ts:1729-1738`
- **条目字段**：`{ id: 'qq-rules', appId: 'qq', kind: 'merged', title: 'QQ', desc: 'QQ 聊天规则整块（表情包/小表情/特殊消息/动作描写/语音条告知）', members: ['qq-sticker-recv', 'qq-emoji-code', 'qq-rich-rules', 'qq-sticker-off', 'qq-action-desc', 'qq-action-desc-off', 'qq-ai-voice'], templateMembers: ['qq-sticker-recv', 'qq-emoji-code', 'qq-rich-rules', 'qq-action-desc', 'qq-ai-voice'], templateOverrides: { 'qq-rich-rules': '{{richRules}}' } }`
- **触发场景**：QQ 单聊每个 AI 回合（`buildPersonaPrompt` → `promptGroupParts('qq-rules', …)`）。组关闭 = QQ 不再注入任何沉浸规则；组编辑 = 编辑版大模板整块接管（`{{richRules}}` 填入当前表情包动态规则）。
- **默认拼装**（见下方各成员条目，按序拼接）。

## 2. qq-sticker-recv —— QQ·对方表情包回应
- **文件+行号**：注册表 `src/lib/prompt-entries.ts:566-578`（`chatRuleEntries`，depth 40/order 0）；QQ 端实际文本 `src/components/apps/qq.tsx:1685-1688`
- **触发场景**：QQ 单聊每回合（表情包开关无论开关都注入——AI 需要理解用户发表情的含义）。
- **原文**（`STICKER_RECV_RULE`，与微信逐字一致）：

```
出现在对方（用户）消息里的「[发送了表情：XX]」表示对方发来一张含义为「XX」的表情包，你要理解并自然回应表情的含义（可以调侃或接住情绪），不要字面复述括号内容。
```

## 3. qq-emoji-code —— QQ·内置小表情代码
- **文件+行号**：注册表 `src/lib/prompt-entries.ts:579-595`（depth 41）；实际文本 `src/lib/ios/emoji-codes.ts:86-90`（`EMOJI_CODE_RULE`）
- **触发场景**：QQ 单聊/群聊，表情包开关开启时注入（`stickersOn`）。
- **原文**：

```
【内置小表情】消息里的方括号表情代码（如 [微笑][呲牙][裂开]）是对方发的内置小表情，括号里的名字就是含义，理解并自然回应即可；你自己想发这类小表情时，直接在句子里写 [内置表情的意思]（意思必须来自下面表情包清单里的内置表情，写意思不写 ID，如清单里有「xx-微笑:微笑」就输出 [微笑]），可与文字混排（如「哈哈[捂脸]」「晚安[月亮]」）；写错名字对方只会看到文字；要不要发表情完全自然决定，不要每句都带。
```

## 4. qq-rich-rules —— QQ·特殊消息标记（动态组装）
- **文件+行号**：注册表 `src/lib/prompt-entries.ts:596-610`（depth 42）；实际文本由 `src/lib/chat-rich.ts:756-804 buildRichRules(stickers, { familyCard: false })` 现场组装（QQ 恒传 `familyCard=false`，见 `qq.tsx:1675`）
- **触发场景**：QQ 单聊每回合；关闭本条 = 停止教 AI 发红包/转账/位置/表情包/歌曲卡片。
- **原文**：见「五、特殊消息与动作类」第 22-29 条（QQ 版 = 亲属卡教学全部剔除）。注册表占位说明文本：

```
【特殊消息】红包/转账/位置/表情包/分享歌曲的方括号输出标记教学与表情包清单（由 buildRichRules 按当前表情包动态组装；关闭本条 = 停止教 AI 发这些卡片）。
```

## 5. qq-sticker-off —— QQ·表情包禁用令
- **文件+行号**：注册表 `src/lib/prompt-entries.ts:611-625`（depth 43）；实际文本 `src/lib/sticker-toggle.ts:66-68`（`STICKER_OFF_RULE`）
- **触发场景**：QQ 单聊/群聊，表情包开关**关闭**时注入。
- **原文**：

```
【表情与 emoji 禁用（对方已关闭表情包）】你不发表情包：禁止输出 [表情包:ID]、[表情:XX]、[发送了表情：XX] 等任何形式或变体的表情标记；你也不发任何 emoji 表情符号（如 😀😂🤣😍🎉✨🔥👍❤☀ 等一律禁止）。对方发来的表情你照常理解含义，但你的回复一律纯文字。
```

## 6. qq-action-desc —— QQ·动作描写格式（开）
- **文件+行号**：注册表 `src/lib/prompt-entries.ts:626-642`（depth 44/order 0）；实际文本 `src/lib/action-desc.ts:92-96`（`ACTION_DESC_RULE`）
- **触发场景**：QQ 单聊/群聊，动作描写开关开启时。
- **原文**：

```
【动作描写格式】你可以在回复里用一对星号包裹动作、神态与情景描写（只包裹描写本身，例如 *笑了笑*、*她端起茶杯抿了一口*、*窗外雨声渐起*），描写会以灰色小字独立显示在聊天中间，正文照常写在星号外面。动作描写尽量单独占一行，写在它相邻正文的前面或后面，不要把描写和正文挤在同一句里；星号只用来包裹动作描写，不要用在普通文字的强调或标题上；每条回复里的动作描写要简短自然（一两处即可），不要整条回复全是描写，也不要每条消息都加描写。
```

## 7. qq-action-desc-off —— QQ·动作描写禁用（关）
- **文件+行号**：注册表 `src/lib/prompt-entries.ts:643-657`（depth 44/order 1）；实际文本 `src/lib/action-desc.ts:99-101`（`ACTION_DESC_OFF_RULE`）
- **触发场景**：QQ 单聊/群聊，动作描写开关关闭时。
- **原文**：

```
【动作描写禁用（对方已关闭动作描写）】禁止输出任何动作、神态、情景描写：不要写「*...*」这类被星号包裹的内容，也不要用括号单独补充动作或场景；回复一律只写你嘴里说出来的话，像真人打字一样。
```

## 8. qq-ai-voice —— QQ·语音条送达告知（100-e）
- **文件+行号**：注册表 `src/lib/prompt-entries.ts:658-670`（depth 45）；实际文本 `src/components/apps/qq.tsx:1658-1659`（`AI_VOICE_DELIVERY_RULE`）
- **触发场景**：QQ 单聊，AI 语音频率开关非「关闭」档时（`aiVoiceOn`；文字消息投递时会按频率静默升级为语音条）。

```
【读懂拼音缩写】对方发的纯英文字母串（如 wyxn、hxhx、xswl、yyds）基本都是中文的拼音首字母缩写——把每个字母当作一个字的拼音首字母逐字拆解、组词成句，并结合你们正在聊的话题和关系选最贴切的含义，绝不要当成无意义乱码，更不要瞎猜一个错误意思：
- 常见缩写按固定含义理解：wyxn=我也想你（w-我 y-也 x-想 n-你）、hxhx=好想好想、xswl=笑死我了、yyds=永远的神、nsdd=你说得对、dbq=对不起、bdjw=不懂就问、u1s1=有一说一、zqsg=真情实感、pyq=朋友圈、awsl=啊我死了（被甜到/萌到）、gkd=搞快点、srds=虽然但是、kdl=磕到了、plmm=漂亮妹妹、3q=谢谢；
- 拆解优先级：先套上面的常见缩写表；表里没有的按拼音首字母逐字组词（像 wyxn 就拆成 w-我/y-也/x-想/n-你 这样组出通顺的话）；叠字母（hxhx、kkl）优先当叠词（好想好想、看看）；夹数字的按谐音（3q=谢谢、666=厉害、u1s1=有一说一）；
- 对方问「你知道XX是什么意思吗」时，必须先按拆解规则给出正确含义再回应情绪（比如 wyxn 是「我也想你」，绝不能答成「我爱你想你」这类拆错的答案）；拆不准时结合你们的关系和话题挑一个最自然、最贴近对方心意的解释，不要硬编一个明显不对的。
```

```

{turnLine：群聊行或私聊行}
```

```
2. 世界书设定（理解世界观、角色背景与关系时以此为准）；
3. 角色人设（性格与说话风格——世界书改变的是背景认知，不改变说话方式与输出格式）；
4. 长期记忆和核心记忆（稳定的事实画像）；
5. 记忆碎片（最新进展：同一件事与旧画像不一致，说明情况有了变化，按更新的理解）；
6. 最近聊天记录；
7. 用户新消息（必须第一时间直接回应，任何设定、记忆都不能成为无视或压制对方当前发言的理由）。
冲突处理：
1. 世界书与记忆冲突时，世界观类内容以世界书为准；
2. 世界书内部多条设定冲突时，按条目优先级排序；
3. 世界书与角色人设冲突时，世界观与背景类内容以世界书为准，但人设【禁止事项】（安全与格式红线）始终优先于世界书；
4. 如果当前对话里你们还处于互不相识/刚换新身份的陌生阶段，涉及你们共同经历的世界书设定先不要生效，等关系对上再自然使用，以免穿帮。
```

# 十三、历史消息序列化格式（进入 LLM 上下文的文本口径）

> 这些不是独立的「规则提示词」，而是**拼进 messages 数组的历史文本格式**——AI 读到的内容完全由它们决定，且其中多处格式被上方规则显式引用（如 [M编号]、[图片 ID:…]），故完整收录。

## 单聊（qq.tsx:5214-5344，base 取最近 20 条）
- **过滤**：撤回/错误/通知行/申请卡不进历史；错误占位（`〔…`/`（消息发送失败`/`（AI`/`（对方暂时` 开头）排除。

# 附：QQ 链路上其他与 LLM 相关的边界说明（非独立提示词）

1. **记忆提取/总结**：QQ 每轮 AI 回合结束后 `memAfterAiTurn(peer.id,'qq',…)`（`qq.tsx:5786-5800`）触发服务端 `/api/memory/extract`、`/api/memory/summarize`——提取/总结 prompt 属于「记忆模块」（注册表 appId='memory'），不在 QQ 文件内，由记忆提取任务覆盖；QQ 侧仅传视角名（双方真实名字）与 app='qq'。

4. **纯 UI 文案**（聊天页 toast、卡片按钮、详情页文案等）不发给 LLM，未收录。
