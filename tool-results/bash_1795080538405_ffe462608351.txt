 wechatbot 中文 📦 Overview 📡 Protocol 🟢 Node.js 🐍 Python 🔵 Go 🦀 Rust 🤖 Pi Agent Overview QR login flow Message loop Typing indicator Media upload Session recovery Headers Endpoints context_token AES crypto Error codes SDK mapping The WeChat iLink Bot API is an HTTP/JSON protocol used by the WeChat ClawBot feature. Base URL: https://ilinkai.weixin.qq.com . CDN: https://novac2c.cdn.weixin.qq.com/c2c . 
 Overview The protocol has three phases: login (QR scan), messaging (long-poll + send), and media (CDN upload/download with AES encryption). The critical concept is context_token — every reply must echo it back from the incoming message. 
 QR login flow Login uses a QR code scan-and-confirm pattern, similar to WeChat Web login. Status machine: wait → scaned → confirmed (or expired → request new QR) The bot_token is a Bearer token used for all subsequent API calls. baseurl may differ from the default — always use the returned value. 
 Message receive/send loop Messages are received via long-polling ( getupdates ), not WebSocket. The server holds the connection for ~35 seconds. Key rules: 
--
 ret: 0 = success; ret: -14 = session expired 
 Messages contain context_token — must echo it back in replies 
 
 Typing indicator flow Showing &quot;对方正在输入中&quot; requires two API calls: first get a typing_ticket , then send it. Tips: Cache typing_ticket per user (valid ~24h). status: 1 = start, status: 2 = stop. For long operations, send status: 1 every 5 seconds as keepalive. 
 Media upload/download Media files (images, videos, files, voice) are encrypted with AES-128-ECB before upload to the WeChat CDN. 
 Session expiry &amp; recovery Sessions expire after some time. The server returns errcode: -14 on any API call when this happens. All SDKs handle this automatically — the user just needs to scan a new QR code. 
 Common request headers Every business POST request requires these headers: Content-Type: application/json
--
Authorization: Bearer &lt;bot_token&gt;
X-WECHAT-UIN: &lt;base64(String(random_uint32))&gt;
 All request bodies include: 1 { &quot;base_info&quot;: { &quot;channel_version&quot;: &quot;2.0.0&quot; } } X-WECHAT-UIN is generated fresh per request: random 4 bytes → uint32 → decimal string → base64.

 context_token — the critical concept context_token is the most important concept in the iLink protocol. It&#x27;s not optional — without it, replies cannot be routed to the correct WeChat conversation. Rules: 
 Every incoming message contains a context_token 
 Every outgoing sendmessage must include it 
--
 If 32 bytes and all hex ASCII → hex decode → 16 bytes 
 Encrypted size: ceil((rawSize + 1) / 16) * 16
